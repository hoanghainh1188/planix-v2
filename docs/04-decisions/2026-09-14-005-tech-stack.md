# Tech stack: TypeScript full-stack monorepo + PostgreSQL
- Ngày: 2026-09-14
- Feature liên quan: `005-organization-access` (issue #5) — áp dụng cho toàn dự án
- Câu hỏi gốc: Constitution (Ràng buộc nền tảng) yêu cầu chốt tech stack bằng decision record trước khi
  sinh code trong `src/`. Đánh giá 3 phương án trong `/speckit-plan`: (A) TypeScript full-stack,
  (B) Kotlin + Spring Boot, (C) Python + Django — tiêu chí: Nguyên tắc I–IV, i18n/UTC, hiệu năng OI-14,
  đội nhỏ.
- Quyết định: **Phương án A — TypeScript full-stack.**

  | Lớp | Lựa chọn (bản kiểm tra trên npm registry 2026-09-14) |
  |---|---|
  | Runtime | Node.js 24 LTS |
  | Ngôn ngữ | TypeScript **6.0.x** (pin `<6.1` — `typescript-eslint` 8.x chưa hỗ trợ TS 7) |
  | Monorepo | npm workspaces: `packages/core` (domain thuần), `apps/server`, `apps/web` |
  | Backend | NestJS 12 (Express adapter) |
  | Database | PostgreSQL 17, Drizzle ORM 0.45 + `pg` 8 (driver) + drizzle-kit migration |
  | Frontend | React 19 + Vite 8 + React Router 7 + TanStack Query 5 |
  | Validation/contract | zod 4 (schema dùng chung server–web) |
  | i18n | i18next 26 + react-i18next 17 (VI, EN) |
  | Rate limit | `express-rate-limit` 8 làm middleware Express (sửa đổi 2026-09-15 — `@nestjs/throttler` 6.5 chưa hỗ trợ NestJS 12) |
  | Test | Vitest 5 + `@vitest/coverage-v8`, cấu hình `vitest.config.ts` với `test.projects` (Vitest ≥ 4 đã bỏ file workspace); Supertest + `@nestjs/testing`; Testcontainers (PostgreSQL thật); Playwright cho E2E luồng chính |
  | Lint/format | ESLint 10 + typescript-eslint 8, Prettier 3 |
  | Mật khẩu | argon2id (`argon2`) |

  **4 ràng buộc bắt buộc cho Nguyên tắc I (điều kiện chấp nhận phương án A):**
  1. Mọi tiền và chỉ số trong `packages/core` dùng kiểu `Decimal` riêng (bọc `decimal.js`); không export
     thao tác số học trên `number` cho giá trị tài chính.
  2. Tiền/chỉ số qua API và JSON luôn là **chuỗi** thập phân; schema zod từ chối `number`.
  3. PostgreSQL dùng `NUMERIC`; driver `pg` trả `NUMERIC` dạng chuỗi — cấm cấu hình parser chuyển sang
     `number`.
  4. ESLint rule cấm kiểu `number` và toán tử số học trên giá trị tài chính trong module tài chính, **có test
     chứng minh rule bắt được vi phạm**.

  **Bố cục code theo feature (khớp `CLAUDE.md`):** mỗi package có `src/features/<slug>/` cho code riêng
  feature và `src/shared/` cho phần dùng chung. Thư mục `src/` và `tests/` rỗng ở root template bị thay bằng
  bố cục monorepo.

  **Lớp chắn cô lập tổ chức:** kiểm tra ở tầng ứng dụng (mọi truy vấn nhận `organizationId` từ ngữ cảnh
  phiên) **và** PostgreSQL Row-Level Security; ứng dụng kết nối bằng role không phải owner để RLS không bị
  bỏ qua.

  **Lý do chọn A:** một ngôn ngữ cho cả server và web (đội nhỏ, dùng chung schema/kiểu); khớp tooling đã có
  trong repo (`npm` trong `.claude/settings.json`); hiệu năng CPM O(V+E) cho 10.000 task dư thừa so với
  ngưỡng 2 giây. Rủi ro float của JS được khống chế bằng 4 ràng buộc trên.
  **Phương án bị loại:** B (an toàn số học tốt nhất nhưng 2 ngôn ngữ, nặng cho đội nhỏ — là phương án dự
  phòng nếu 4 ràng buộc tỏ ra không đủ); C (2 ngôn ngữ, kiểu dữ liệu lỏng hơn).
  > **Sửa đổi 2026-09-15** (phát hiện khi `/speckit-implement` T005/T007): (1) thay `@nestjs/throttler` bằng
  > `express-rate-limit` 8.7 — peer `express >= 4.11`, khớp Express 5 của NestJS 12; hành vi giữ nguyên (giới hạn
  > theo IP cho `/api/v1/auth/*`, `/api/v1/invitations/*`, trả `429 RATE_LIMITED`); (2) `vitest.workspace.ts` →
  > `vitest.config.ts` + `test.projects`. Người quyết định: @hoanghainh1188.
  >
  > **Sửa đổi 2026-09-15 (phát hiện khi implement T087, chọn phương án A):** rate limit IP chỉ đếm request
  > **thay đổi trạng thái** (POST/PUT/PATCH/DELETE) dưới `/api/v1/auth/*`, `/api/v1/invitations/*` — đăng nhập,
  > đặt lại mật khẩu, chấp nhận lời mời. Request đọc (GET/HEAD/OPTIONS) không bị đếm: web gọi `GET /auth/session`
  > ở mọi lần tải trang nên 30 lần/15 phút làm người dùng (hoặc cả văn phòng chung IP) bị 429; token lời mời
  > 256-bit nên `GET /invitations/{token}` không cần giới hạn. Chống đoán mật khẩu giữ nguyên (rate limit POST +
  > khoá tài khoản 5 lần/15 phút). Loại: B (chỉ nới giới hạn cho E2E — lỗi production vẫn còn), C (liệt kê từng
  > endpoint — dễ sót khi thêm route). Người quyết định: @hoanghainh1188.
  >
  > **Ghi chú bắt buộc khi chốt Deploy (2026-09-15, security review #5):** rate limit `express-rate-limit`
  > khoá theo `req.ip`; hiện **chưa** đặt `trust proxy` (Express mặc định `false`). Khi chạy sau reverse proxy /
  > load balancer phải đặt `app.set('trust proxy', <số hop hoặc CIDR của proxy>)` đúng topology — **không dùng
  > `true`**. Để `false` sau proxy → mọi client chung một bucket (ai cũng khoá được `/auth/*`,
  > `/invitations/*` của người khác); để `true` → `X-Forwarded-For` do client giả mạo, vượt rate limit. Kèm test:
  > `X-Forwarded-For` giả không tạo bucket mới. Mục "## Deploy" của `CLAUDE.md` phải trỏ về ghi chú này.
